# Feedback from the ceteris project, 2026-11-12

Source: one month of running a large Rust project (deterministic agent-based simulator, ~280 ADRs, daily agent threads) with a coordinator session plus one-task threads, before Mandate existed. Compared against `docs/spec/` and ADRs 0001-0014 at `4360f84`. Evidence is from project memory and thread history; claims without a cited event are judgment.

Ceteris decided on 2026-11-12 to defer adoption until the CLI and template ship. This is input, not a request to merge anything.

## Context

- Roles: owner (equivalent to the BDFL), a coordinator session that routes work and keeps memory, task threads that open PRs.
- Constraints that shaped the process: token budget, one thread in the queue at a time, a sandboxed laptop that cannot merge, a private repository.

## What worked

1. **Registry plus CI check for decisions.** On 2026-11-01 decisions moved to a TOML registry (`rows.toml`) with a CI `check`. Numbers are assigned only in the PR that writes them. Before this, 16 branches edited the same design file and numbers collided. Parallels `mandate-check` contiguous numbering; keep it.
2. **Spec before code, deviations as proposals.** Every behavioural change cites a spec section or an ADR. Review is cheap because the question "which decision does this implement" has an answer.
3. **Path guard on `.github/` and CODEOWNERS for agent branches.** One CI rule, no incidents. Supports ADR 0013.
4. **One issue, one PR, one task per thread, turn cap, "stop and report blocked after two failed attempts".** Matches `agents.md` Work and Blocked. Runaway retries stopped once the cap was written into every thread prompt.
5. **Question cards with a recommended option.** Decisions front-loaded as multiple choice (2-4 options, one recommended, a one-line consequence each). The owner answers from a phone in seconds. On 2026-11-12 a single card replaced a long exchange about whether to adopt a framework. Mandate's `blocked` says "specific question and the options you see"; make the card shape the format.
6. **Short posts: outcome, link, blocker, at most three lines.** The owner reads only what needs action. Matches the digest idea.
7. **Memory under a size cap, pruned.** A 4 KB project memory with decisions, constraints and open blockers only stays loadable by a fresh session. Details in memory rotted within days (see friction 1).
8. **Stage gates per feature: working, right, fast.** "Right" requires a test that fails without the change. Cheap to state, caught real regressions.

## Friction

1. **Stale queue issue.** The single tracking issue for the queue (#179 in ceteris) kept old checkboxes while the live queue moved into memory. New sessions read the issue first and were misled; decided items stayed open for weeks. Cause: two places hold state, only one is kept current. Mandate's issues-as-queue avoids this only if close-out and `mandate next` are the sole sources of order.
2. **Dangling references.** Docs and PRs point at files in a shared project folder (reports, patches, runbooks) that live outside the repository. They are unreviewed, unversioned, and gone if the project is. Rule that would have helped: a repository document may cite only repository paths or released URLs.
3. **Unwired kernels pile up.** About 1,600 lines of new simulation components were merged with green tests and no path from a real run. Each was individually correct and individually gated, so nothing stopped the next. Nine accumulated before an audit found them. The owner then set: at most three unwired at a time, each with a wiring issue, off-by-default switches reviewed at each phase gate. "Done" in `agents.md` (acceptance boxes, tests, CI) does not catch this.
4. **Wiring needs a switch-on test.** Goldens-unchanged-with-the-switch-off proves nothing about the feature. The owner required a behaviour test with the switch on for every wiring PR. Same gap as friction 3: tests can be green while the feature is inert.
5. **Merge-permission contradiction.** The repository instructions said agents may merge ordinary PRs and the owner must decide specs; a later standing message said merge everything on green including spec and RFC PRs. Both lived in different files and sessions followed whichever they read last. Resolved by an ADR, but only after confusion. In Mandate this is the gate list in ADR 0004 vs. a project's wish to relax it.
6. **Decision versus merge.** "Only the owner decides" and "agents merge on green" coexisted by splitting them: the owner picks the option on a card, the agent merges the PR that records it. Mandate's gate conflates approval of the decision with approval of the merge, so a gated PR waits even when the decision was already made elsewhere.
7. **Other agents' messages read as decisions.** A coordinator relaying "the owner wants X" was treated as the owner's word. Rule adopted: only a message authored by the owner, or one quoted verbatim by the server, counts. `agents.md` says "Never act as the BDFL's account" but does not say what counts as BDFL approval in a conversation.
8. **Coordinator context growth.** Coordinator sessions fill up; recycling needs a checkpoint to memory first, and memory over the cap silently loses the tail. No framework piece defines handoff between sessions of the same role (the `handoff` label covers design documents only).
9. **Environment limits are not process.** A laptop sandbox could not merge, force-push or delete branches; a cloud sandbox could not reach some hosts. Work that needed a specific machine stalled until the owner noticed. Mandate has `bdfl` for owner-only work but nothing for "needs machine X".
10. **Instruction drift.** The repository's agent instructions kept naming the old owner and repository after a migration. Mandate's pinned `.mandate/agents.md` with `mandate-check` addresses part of this.

## Proposals

Each is small; none is required to adopt the rest.

1. **Configurable merge permission per gate.** Add to `AGENTS.md` a table: path or detector, `approve` (BDFL approves) or `merge-on-green` (agents merge, decision recorded elsewhere). Default is today's behaviour; a project may relax only paths it lists, never `.github/`, CODEOWNERS or `.mandate/`. Makes friction 5 and 6 an explicit, reviewable choice rather than a silent override.
2. **Define approval.** In `agents.md`: BDFL approval is a review by the BDFL's account on GitHub, or a message authored by the BDFL in the session. Another agent's relay is information, never approval.
3. **Wire-or-park rule.** A new component without a call path from a real run counts as `parked`. Cap parked items per milestone (suggest 3) and require a wiring issue for each. A PR that wires a component must include a test with the switch on. Add a `mandate-check` rule that lists parked items from a front-matter field or a marker file.
4. **Acceptance must include reachability.** Milestone Acceptance lines should name an observable from an end-to-end run, not only "tests pass". Close-out checks it (already in `agents.md` Close-out; make the wording explicit).
5. **Switch review at close-out.** List default-off switches and flags introduced in the milestone; each gets: enabled, an issue with a date, or removed.
6. **State in one place.** Say that issue order is `mandate next`, and that any other queue document (a roadmap checklist, a pinned issue) is generated or forbidden. If a pinned queue exists, `mandate digest` should flag items whose issues are closed.
7. **No out-of-repo references.** `mandate-check` fails on links in `docs/` to paths outside the repository (project folders, local files). Handoff documents are exempt until committed.
8. **Decision card format.** In `agents.md` Blocked: question, 2-4 options, one recommended with a one-line reason, one-line consequence per option. Lets the BDFL answer from the notification.
9. **Labels.** Add `wire` (wiring work for a parked component) and `needs-env` (needs a specific machine or network). Both optional.
10. **Digest additions.** Parked components and their age; open `needs-env` items; gates older than N days; PRs merged without a linked issue.
11. **Session handoff.** Add a short `.mandate/state.md` convention, or document that session memory is out of scope. If memory is used, cap it (suggest 4 KB), store decisions, constraints, frozen names and open blockers only, and never store what a repository file already says.
12. **Cost visibility.** Optional PR-body line with the model and rough token use per task. Ceteris logs one line per completed thread; it made expensive tasks visible and drove the rule that stronger models run only on design and hard debugging.

## Open questions

- Should the `gate` label be split into `gate:decision` and `gate:merge`, so a pre-decided change can be merged by an agent while the decision stays with the BDFL?
- How should a project record that a standing permission (for example merge-on-green) was granted, by whom, and when it expires? An ADR works; a revocation path is missing.
- Who owns the queue when there is a coordinator role between the BDFL and the agents? Mandate has two actors; ceteris had three, and routing, memory and digests landed on the middle one.
- Does one-thread-at-a-time belong in the framework, or is it a project budget rule? It prevented merge conflicts and cost blowups but halves throughput.
- For a private repository, should enforcement fall back to documented convention when rulesets are unavailable on the plan?
- Is a `game` profile playtest gate meaningful for a project that is a pure simulator with no player-facing build yet?

## Not asked for

Ceteris does not ask Mandate to adopt its layout (`rfcs/`, `spec/`, `rows.toml`). The registry check in What worked 1 is the transferable part, not the format.
