## Goal
The `mandate` commands in `docs/spec/cli.md`, so projects are created, run and closed out without hand-applied `gh` steps.

## Scope
- `bin/mandate` dispatcher: `mandate <cmd>` runs `mandate-<cmd>` from `PATH`.
- `mandate init <profile>` and `mandate sync [--upgrade]`, including labels, rulesets and topic, and the required-check refusal in `sync`.
- `mandate status` and `mandate digest [--since] [--post]`, reporting stalled projects, open gates and blocked issues.
- `mandate next [--claim]` with the claim race handled as specified.
- `mandate adr new`, `mandate rfc new`, `mandate milestone new`, with numbers assigned last (#39).
- `mandate handoff`, `mandate block`, `mandate closeout`, `mandate release`.
- Tests for each command against fixtures or a scratch repository.
- Carried from 002: try the design-session instructions in a real design session and record the result (#16).

## Out of scope
- Pilots on yan, db or animal-spirits projects.
- Spec amendments in triage (#18, #27 to #38, #40 to #42), unless the BDFL pulls one in.
- Running agents on a schedule: infra.

## Acceptance
- A new repository created with `mandate init` passes `mandate check` and enforces the gated paths.
- `mandate sync` on this repository is a no-op.
- `mandate closeout` produces the close-out for this milestone.

## Risks
- `init` and `sync` write rulesets and need admin access; agent sessions cannot run them, so they may stay BDFL commands.
- bash 5 is not the macOS default shell.
