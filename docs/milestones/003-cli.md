## Goal
The commands an agent session runs in the milestone loop, so a pilot project can run one milestone under Mandate with the template applied by hand.

## Scope
- `bin/mandate` dispatcher: `mandate <cmd>` runs `mandate-<cmd>` from `PATH`.
- `mandate status`, reporting state, stalled, open gates and blocked issues.
- `mandate next [--claim]` with the claim race handled as specified.
- `mandate block`.
- `mandate new <adr|milestone>` and `mandate number`, with numbers assigned last (#39).
- `mandate closeout`.
- Tests for each command against fixtures or a scratch repository.
- Carried from 002: try the design-session instructions in a real design session and record the result (#16).

## Out of scope
- `mandate init`, `mandate sync`, `mandate release`, `mandate digest` and `mandate handoff`: milestone 004 (proposed in ROADMAP Next).
- Pilots on yan, db or animal-spirits projects.
- Running agents on a schedule: infra.

## Acceptance
- An agent session on this repository claims, works and closes an issue using only `mandate next --claim`, `mandate block` and `mandate status`.
- `mandate new adr` then `mandate number` on two parallel branches yields contiguous numbers after the second merges main.
- `mandate closeout` produces the close-out for this milestone.

## Risks
- bash 5 is not the macOS default shell.
- Spec changes from the 2026-11-14 research pass land while commands are being written; commands follow the merged spec.
